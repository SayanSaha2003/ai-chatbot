# AI Chatbot — Project Notes

## 1. Project Overview
- A simple AI chatbot web application.
- Users can have one continuous conversation with an AI assistant.
- The chatbot sends conversation messages to the backend and receives AI-generated responses from OpenRouter.
- AI responses are streamed to the UI for a ChatGPT-like experience.
- No database, authentication, or sidebar is used.

## 2. Features
- Continuous single conversation
- Send user messages
- Maintain conversation context using a `messages` array
- AI-generated responses using OpenRouter
- Streaming AI responses
- Chat-style user/assistant message bubbles
- Auto-scrollable chat area
- Responsive UI
- Simple navbar and footer
- Loading/error handling can be added as a final improvement

## 3. Tech Stack
- Frontend: React
- Styling: Tailwind CSS
- Backend: Node.js + Express.js
- AI API: OpenRouter API
- Model: `gpt-4o-mini`
- Database: None
- Authentication: None

## 4. Architecture & Data Flow
React → Express API → OpenRouter → `gpt-4o-mini` → Express stream → React UI

### Request Flow
1. User enters a message.
2. React adds the user message to the `messages` array.
3. React sends the conversation to `POST /api/chat`.
4. Express sends the messages to OpenRouter.
5. OpenRouter generates the response using `gpt-4o-mini`.
6. The backend streams the generated text.
7. React reads the response using `ReadableStream`.
8. Each received chunk is added to the assistant message.
9. The UI updates progressively while the response is being generated.

## 6. Database Design
- No database is used.
- Conversation history exists only in React state while the page is open.
- Refreshing the page clears the conversation.

## 7. Authentication & Authorization
- No authentication.
- No authorization.
- No user accounts.
- The application is intentionally kept simple for the first AI project.

## 8. API / Server Actions

### `POST /api/chat`
- Receives the conversation from React.
- Request body contains a `messages` array.

Example:
```text
{
  "messages": [
    {
      "role": "user",
      "content": "Explain React in simple words."
    }
  ]
}
```

### Roles
- `user` — message sent by the user.
- `assistant` — response generated by the AI.

## 9. Important Concepts
### Conversation Context
The chatbot sends the previous conversation messages to the AI instead of sending only the latest message.

```text
messages[]
    ↓
user message
assistant response
user message
assistant response
...
```

This allows the model to understand the previous conversation.

### Streaming AI Responses
Instead of waiting for the complete AI response:

```text
Request → Wait → Complete response
```

the response is received in chunks:

```text
Request
  ↓
Chunk 1
  ↓
Chunk 2
  ↓
Chunk 3
  ↓
...
```

Frontend streaming uses:

```text
response.body.getReader()
```

and:

```text
TextDecoder
```

The chunks are appended to the current assistant message.

### Important Frontend Streaming Logic
```text
reader.read()
    ↓
receive bytes
    ↓
TextDecoder
    ↓
convert to text
    ↓
append chunk
    ↓
update assistant message
```

### Environment Variables
The OpenRouter API key is kept in the backend `.env` file instead of exposing it in React.

```text
OPENROUTER_API_KEY=...
```

The API key should never be placed directly in frontend code.

### API Security
The frontend communicates with the Express backend instead of calling OpenRouter directly.

```text
React → Express → OpenRouter
```

This keeps the OpenRouter API key on the server.

### React State
The conversation is stored using React state:

```text
messages
```

Each message contains:

```text
role
content
```

### Tailwind CSS
Tailwind CSS is used to build the chatbot UI with utility classes.

### Chat Layout
The application uses a viewport-height flex layout:

```text
Navbar
   ↓
Chat
   ↓
Footer
```

The main chat area uses the remaining available height, while the message area can scroll independently.
